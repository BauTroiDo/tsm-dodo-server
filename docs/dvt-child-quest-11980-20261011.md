## Proven source bug fixed

`elseif resultClass == 12 then`

inside the dialogue handler. Here `resultClass` is not the function argument; the other branches use `eventInfo.resultClass`. Replaced **only** this test with:

`elseif eventInfo.resultClass == 12 then`

so `showRole = Role.childNpc` can be selected when a DVT event marks the speaking character as class12. The rest of the message flow is unchanged.

## Why class17 is not enabled with invented values

Authoritative Lua `Data/HumanData.lua` contains `ChildData.New(data)` for **93 bytes** including `kind` (0=None,1=Foster,2=Died,3=Adults), `sex`, `turn`, `element`, skills, feeding times, attributes, item count, and career. `Logic/Role.lua` declares `Role.playerData.child` and `Role.childNpc`. `Common/protocal.lua` receives the child state in **S:069-007** and **S:069-009** (plus update packets 069-008/010/011). The current Kotlin server has no authoritative ChildData persistence/069 state handlers; `PlayerEventState.childSlots` remains an unrelated empty placeholder.

Implementing class17 against `childSlots`, generic follower counts, or an always-true stub would wrongly unlock and reward mission 11980, and could start a child-specific battle without an actual child companion. The secure next milestone is to implement and persist the real child state, then decode each class17 predicate from controlled source data or server reference behavior; preserve fail-closed evaluation until then.
