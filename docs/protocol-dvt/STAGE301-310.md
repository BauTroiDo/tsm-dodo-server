# Batch Steps 301–310 — Extended FollowNpc skills

Status: **COMPLETE — owner build gate pending.**

## Step 301 — Lua GetSkillLv sources
DVT `RoleController:GetSkillLv` proves separate FollowNpc sources: three normal per-pet levels, learned special skill, upgrade skill, exclusive-weapon skill, passive skill and soul skills.

## Step 302 — Special skill semantics
For `npcDatas[npcId].specialSkill`, Lua returns level 1 only when `self.data.specialSkillLearned` is true.

Kotlin equivalent data already exists as `FollowNpcData.canUseSpecialSkill` and `NpcDef.specialSkill`.

## Step 303 — Special skill snapshot
Battle creation now adds `NpcDef.specialSkill` at level 1 only when `canUseSpecialSkill` is true and the ID is positive.

An unlearned configured special skill is not exposed as learned.

## Step 304 — Upgrade skill semantics
Lua returns `npcUpgradeDatas[self.data.upgradeLv].skillLv` for `npcDatas[npcId].upgradeSkill`, only when that upgrade table row exists.

## Step 305 — Upgrade data authority
Server already loads `NpcUpgrade_C.dat` into `GameDataManager.npcUpgradeDefs`; `NpcUpgradeDef.skillLv` is the exact field required by Lua semantics.

## Step 306 — Upgrade skill snapshot
BattleManager now receives `npcUpgradeDefs`.

For a FollowNpc, if `NpcDef.upgradeSkill > 0` and the current `upgradeLv` row has `skillLv > 0`, the battle snapshot adds that skill with the exact table level.

## Step 307 — Normal skills preserved
The Steps 291–300 normal-skill rule remains: first three NpcDef IDs are included only when the individual pet's corresponding skill1Lv/skill2Lv/skill3Lv is positive.

Normal, special and upgrade skills are merged into one authoritative skill-level snapshot.

## Step 308 — Passive boundary
Lua `GetSkillLv` can return `passiveSkillLv`, but that proves lookup semantics, not that the passive is a selectable C:050 command.

This batch does not add passiveSkill to active battle command skills without selection/send evidence.

## Step 309 — Exclusive weapon and soul boundary
Lua resolves exclusive-weapon skills through `ExclusiveWeapon.GetSkill(itemId, enhanceLv)` and soul skills through equipped Soul data.

The current Kotlin battle path does not yet expose equivalent loaded exclusive/soul skill tables. No IDs or levels are fabricated.

## Step 310 — Closure
FollowNpc battle snapshots now reproduce every extended active skill source for which the server already has authoritative DVT-equivalent data: special and upgrade, in addition to normal learned skills.

No Lua changed. Passive/exclusive/soul remain explicit audit boundaries.
