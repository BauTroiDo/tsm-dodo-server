# Batch Steps 101–110 — Mid-round control and NPC fallback

## Step 101 — Control audit
Client FightField.CheckCanAct and IsCanControl reject Seal plus Faint Chaos/Taunt. Server already modeled Seal and Chaos; Taunt is not yet in BattleStatus.

## Step 102 — Action-time control
BattleFighter exposes isActionBlocked from the authoritative grouped control state.

## Step 103 — Mid-round Chaos
A command queued before a faster actor inflicts Chaos is now cancelled when the affected fighter reaches its AGI turn.

## Step 104 — Mid-round Seal
The same action-time recheck continues to cancel queued commands when Seal lands before the fighter acts.

## Step 105 — Death-before-turn
Existing resolveRound alive recheck is retained: a fighter killed earlier in the AGI queue cannot execute its queued action.

## Step 106 — NPC insufficient-SP audit
Step57 prevented NPC from queueing an unaffordable skill but left the NPC with no action for the round.

## Step 107 — NPC basic fallback
When the selected NPC skill cannot be paid, the server now queues HAND_FIGHT_SKILL_ID against a living enemy instead of silently losing the turn.

## Step 108 — Side correctness
The fallback target is selected from the opposing living side according to npc.isPlayerSide.

## Step 109 — Remove scalar mapper
BattleInstance.statusGroup(BattleStatus) became dead code after groupedStatuses began carrying the EFightStatusKind-compatible key directly. Removed to avoid two diverging group definitions.

## Step 110 — Build gate
Run ./gradlew test build. Taunt and status 174 remain unmodeled until their concrete skill/status mappings are proven.
