# Batch Steps 171–180 — Explicit dispel/remove semantics

## Step 172 — Group membership is skill-specific
Lua does not define "dispel" as clear-all by default. Each status-group handler has its own explicit clear-skill list.

Examples:
- 10009 clears Seal + Vary, not Faint/Spec/Strong.
- 20007 clears Spec.
- broader status-release skills appear in multiple group clear lists.

Kotlin clear lists already mirror these Lua branches and must remain group-scoped.

## Step 173 — Client clear mechanism
For S:050-001, `RunEffect` sees status `Attr_Kind`, converts it to `EFightStatusKind`, then calls:
`target:HandleStatus(statusKind, aEffect.skillID)`.

The clear skill ID is therefore meaningful client data. The corresponding group handler maps that clear skill to `EStatus.None` / `ESkill_Kind.Dis`.

## Step 174 — Proven server/client mismatch
Before this batch Kotlin called `clearGroupedStatus()` server-side, but pure dispels returned `attrChanges = emptyList()`.

Result: authoritative server status was cleared while the Lua client could receive no status `Attr_Kind`, so `HandleStatus(group, dispelSkillId)` was not triggered for the cleared group.

## Step 175 — Pure dispel wire fix
Pure dispel target results now include one zero-value S:050-001 status attribute for each group listed by Lua for that skill:
- Seal -> EAttribute.SEAL
- Vary -> EAttribute.VARY
- Faint -> EAttribute.FAINT
- Spec -> EAttribute.SPEC
- Strong -> EAttribute.STRONG

The packet action keeps the actual dispel skill ID, allowing Lua to resolve the group to None.

## Step 176 — No over-clear
Only `clearGroups(skillId)` is serialized and cleared. Coexisting groups absent from that Lua skill's branch remain untouched.

## Step 177 — Mixed damage/dispel propagation
The same dispel attributes are seeded into the normal result path before damage/status calculation. Therefore a non-pure skill can preserve its ordinary HP/SP result while also telling Lua exactly which status groups were cleared.

No damage formula was changed.

## Step 178 — Natural expiry remains separate
Natural duration expiry continues to use S:053-001 `col,row,statusKind,skillId`.

Explicit dispel during an action uses S:050-001 status Attr_Kind plus the action's dispel skill ID. These are separate client-proven paths and must not be conflated.

## Step 179 — Regression coverage
Extended `DvtBattleStatusExecutionTest` with skill 10009:
- preloads Seal, Vary and Faint simultaneously;
- verifies only Seal + Vary are cleared server-side;
- verifies S:050-001 exposes exactly SEAL + VARY;
- verifies Faint survives;
- verifies no fake HP change is emitted.

## Step 180 — Batch closure
The explicit-dispel path now follows Lua end-to-end:
Lua clear list -> Kotlin group mutation -> S:050-001 status Attr_Kind -> Lua `HandleStatus(group, dispelSkillId)`.

No Lua file was modified. No unproven dispel formula was introduced.
