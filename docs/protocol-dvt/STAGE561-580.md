# Batch Steps 561–580 — PC-original combo packet grouping

Status: **PASS — user confirmed build/test after PC-original combo packet grouping.**

## User/runtime requirement
TS combat supports combined attacks: compatible consecutive team attacks should animate together as a combo rather than being artificially separated by command pacing.

## Primary DVT packet behavior
FightManager.RevAttackSkill parses every action embedded in one S:050-001 and starts their attack state machines during the same receive pass. This is the packet behavior needed to present a combo.

## Secondary PC-original semantics
BattleAbstract.checkCombo(index) returns true when:
- both adjacent commands are skill commands;
- both skills are physical (skill_type == 1);
- both commands target the same cell;
- the joining attacker is not disabled/dead.

The inspected PC source explicitly says combo is 100% regardless of AGI and level. Commands are already ordered by AGI before this check.

BattleAbstract.execCommand serializes the first command plus every following checkCombo command into ONE 0x32/1 packet, then broadcasts that packet. Non-combo commands are sent in separate packets.

## Kotlin mapping
BattleFighter.checkCombo already implements the same physical/same-target adjacency rule after AGI sorting.

The 541–560 pacing patch accidentally emitted every ActionResult separately, losing the PC presentation semantics.

## Patch
- ActionResult now records comboWithPrevious at resolve time.
- BattleManager groups consecutive ActionResults when comboWithPrevious=true.
- Each combo group is serialized into one S:050-001.
- Independent groups remain separate and keep command pacing between groups.
- Existing AGI ordering and combo damage multiplier are unchanged.

## Runtime gate
Run ./gradlew test build.
Test:
1. player + pet/team member use compatible physical attacks on the same target;
2. verify the combo members animate together/linked;
3. verify an independent enemy command is not merged into that combo;
4. verify non-combo player/enemy actions remain sequential rather than simultaneous.

AGI-proximity is NOT added because the inspected PC original explicitly does not use AGI/level as a combo gate. If DVT-specific Lua/data evidence later proves a mobile-only AGI threshold, DVT evidence overrides this PC fallback.

## Gate result
User reported PASS after pulling the combo-grouping patches. Keep this behavior as the combat baseline unless later DVT-specific evidence proves a different combo rule.
