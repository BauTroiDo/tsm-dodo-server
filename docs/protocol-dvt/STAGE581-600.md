# Batch Steps 581–600 — DVT cumulative battle EXP

Status: **PRODUCTION PATCHED — build/runtime gate pending.**

## Runtime symptom
After PvE, the player can level up, but the EXP bar remains at 0% and the client does not reflect meaningful progress.

## DVT Lua authority
UIStatus.SetExpSlider uses:
- maxValue = Calc.GetUpExp(level + 1, turn)
- value = exp - Calc.GetNeedTExp(level, turn)

Calc.GetNeedTExp(level, turn) sums GetUpExp(i, turn) from i=1 through level.

Therefore EAttribute.Exp is cumulative EXP, not remainder EXP within the current level.

S:008-001 is the correct live attribute packet:
attrKind Byte + sign Byte + value Int32 + arg Int32.
Role.SetAttribute updates EAttribute.Exp from the absolute value.

## Kotlin mismatch
Normal BattleManager.distributeExp previously:
1. added reward EXP;
2. compared against one level cost;
3. subtracted that cost from state.exp on level-up;
4. sent the remainder as EAttribute.EXP.

That remainder is incompatible with DVT UIStatus, which subtracts the cumulative threshold again. The result clamps/displays as zero/invalid progress.

## Patch
- StatSystem.calculateNeedTotalExp mirrors Calc.GetNeedTExp for normal turns.
- state.exp remains cumulative and is never decremented on level-up.
- level-up checks cumulative EXP against NeedTExp(level + 1).
- S:008-001 continues to send the absolute cumulative EXP.
- cumulative EXP + level are persisted through CharacterRepository.updateExpAndLevel.

## Existing-character note
Characters whose DB EXP was already stored using the old remainder semantics may still have an invalid historical EXP value for their current level. This patch fixes all new battle EXP. A migration/rebase for existing rows should only be added after confirming the desired recovery rule, because the already-consumed historical EXP cannot be reconstructed exactly from a remainder alone.

## Runtime gate
Run ./gradlew test build.
Then fight without leveling and verify EXP percentage increases.
Fight across a level boundary and verify the new level starts with the correct nonzero remainder percentage when applicable.
Relog and verify the EXP bar remains unchanged.
