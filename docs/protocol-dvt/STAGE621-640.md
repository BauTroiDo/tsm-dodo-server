# Batch Steps 621–640 — DVT self-only battle skill target authority

Status: **PRODUCTION PATCHED — owner build/runtime gate pending.**

## Scope

Continue after the locked 601–620 battle reward-chat PASS baseline. This batch audits command-time target authority only; it does not change battle damage, status RNG, escape RNG, catch outcome semantics, combo grouping, EXP, or reward chat.

## Lua DVT authority

`FightRoleController.DoClick` has an explicit special-case before `CheckSkillTargetLegal`:

- skill 13008
- skill 14002
- skill 20006

For those three IDs, the command is rejected unless `FightField.conIdx == self.index`.

At command time:
- `fightRole = FightField.fightHum[FightField.conIdx]` is the caster;
- `self` is the selected target;
- C:050-001 then serializes caster col/row followed by selected target col/row.

Therefore these three skills have a client-proven **self-target-only** contract. This is stronger than the generic fightWay same-side/enemy-side legality rule.

## Kotlin mismatch

`BattleInstance.setPlayerAction` validated:
- actor ownership;
- duplicate command state;
- alive/dead target rules;
- generic fightWay side legality;
- forbidden skills;
- SP;
- catch/item/bow/summon restrictions;
- learned-skill ownership.

But it did not enforce the DVT self-only exception for 13008/14002/20006.

A crafted C:050-001 could therefore queue one of these skills against a different grid occupant and receive S:053-005 ACK even though the DVT client itself refuses that target.

## Patch

Added a command-time `SELF_ONLY_SKILLS = setOf(13008, 14002, 20006)` gate.

For those IDs, Kotlin now requires:
`targetCol == fighter.col && targetRow == fighter.row`.

Invalid non-self targets are rejected before the action is queued, so no authoritative ACK is emitted by the normal handler path.

Regression coverage verifies:
- all three Lua-listed IDs reject another target;
- a self-target command remains accepted.

## Evidence boundary

Skill 14002 (Espace) has fightWay-related escape restrictions and a concrete Lua presentation script, but this batch does **not** invent or change its authoritative escape-success/RNG semantics.

Likewise this patch does not alter the effect formulas of 13008 or 20006. Only the target contract directly proven by Lua is enforced.
