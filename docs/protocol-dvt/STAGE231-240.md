# Batch Steps 231–240 — Queue target legality and revive exception

Status: **COMPLETE — owner build gate pending.**

## Step 231 — Lua revive selection authority
DVT `FightField.UpdateSelectFrame` treats `fightWay == 8` specially and opens selection with the dead-target mode enabled.

This is stronger than a generic friendly-skill assumption: fightWay 8 is allowed to select dead friendly occupants.

## Step 232 — Lua side legality
`FightRoleController:CheckSkillTargetLegal` includes fightWay 8 in the friendly-only set. A revive target must therefore be on the caster's side.

## Step 233 — Proven queue mismatch
Before this batch, `BattleInstance.setPlayerAction` rejected `target == null || !target.isAlive` before inspecting the skill's fightWay.

Therefore a valid DVT fightWay 8 command targeting a dead ally could never reach the revive-aware resolver implemented in Steps 191–210.

## Step 234 — Separate existence from life-state validation
Queue validation now first requires that the selected grid occupant exists, then loads the skill definition and derives whether it is fightWay 8.

This avoids treating every dead occupant as universally invalid before skill semantics are known.

## Step 235 — Revive dead-target rule
For fightWay 8:
- dead target is accepted by the life-state gate;
- living target is rejected.

The existing friendly-side legality check still runs afterward, so a dead enemy is not accepted as a revive target.

## Step 236 — Ordinary skill dead-target rule
For every non-revive skill, the existing alive-target requirement remains.

Normal heal/buff, attack and other skill commands cannot gain dead-target access from this patch.

## Step 237 — Resolver alignment
Queue semantics now match `BattleSkillResolver` / `BattleGrid.resolveTargets(... deadTargetsOnly=true)` from Steps 191–210.

The command accepted by C:050 can therefore reach the same dead-target contract used at execution.

## Step 238 — No fallback to living target
The revive resolver remains dead-target-only and SINGLE revive has no living-target fallback.

Thus both queue and execution reject a living selection for fightWay 8.

## Step 239 — Regression coverage
Extended `DvtBattleCommandSemanticsTest` with:
- fightWay 8 accepts a dead friendly target;
- fightWay 8 rejects a living friendly target;
- ordinary friendly skill still rejects a dead target.

Existing duplicate-command and dead-actor tests remain.

## Step 240 — Batch closure
The C:050 authoritative queue no longer blocks valid DVT revive commands before execution, while ordinary target legality stays strict.

No Lua file changed. No revive formula changed. No general permission to target dead fighters was introduced.
