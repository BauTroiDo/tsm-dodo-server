# Batch Steps 601–620 — Battle reward system-chat visibility

Status: **PRODUCTION PATCHED — build/runtime gate pending.**

## Symptom
Battle EXP progression works and the EXP gauge is confirmed PASS, but the system/chat area shows no reward text after defeating an NPC.

## DVT Lua evidence
protocal.lua:
- S:002-000 is the system-chat packet and calls Chat.ReceiveMessage(EChannel.System, data).
- Chat.ReceiveMessage ultimately calls Chat.AddMessage, which updates UINewChat.
- S:002-010 is a separate server-text broadcast mechanism whose bit1 also inserts into EChannel.System.
- S:008-001 EAttribute.Exp only updates Role attributes/UI. It does not add a chat message.

## Kotlin mismatch
BattleManager awarded EXP and gold and synchronized their state, but never emitted any system-chat reward message.

ChatResponseSender already implements the DVT S:002-000 layout for a single player, exposed through ResponseSender.sendSystemMessage.

## Patch
After successful PvE reward application:
- EXP: send `Nhận được <exp> điểm kinh nghiệm.`
- Gold: send `Nhận được <gold> vàng.`

This uses the existing S:002-000 parser contract rather than inventing a new battle opcode.

The repository does not contain the DVT localization string table needed to prove the exact S:002-010 string IDs for the original localized reward sentence, so this batch deliberately uses the proven S:002-000 system-channel path.

## Runtime gate
Build, defeat one NPC, and verify the system/chat area displays both EXP and gold reward lines while the already-passing EXP gauge remains correct.
