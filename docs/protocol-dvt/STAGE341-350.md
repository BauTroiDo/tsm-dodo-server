# Batch Steps 341–350 — Manual battle command serialization

Status: **COMPLETE — owner build gate pending.**

## Step 341 — Correct SetConSkill semantics
Fresh DVT evidence corrects the prior boundary: `FightField.SetConSkill` does NOT call `FightField.CaseSkill`.

SetConSkill directly stores `fightHum[conIdx].useSkID = skillID` after its explicit non-battle/bow/summon checks.

## Step 342 — CaseSkill is a different path
`FightField.CaseSkill` is therefore not the authority for manual UIFight command selection.

Its GetSkillLv gate must not be blindly imposed on built-in manual commands 15002/17001/18001.

## Step 343 — C:050 serialization
`FightRoleController.DoClick` serializes manual skill commands as:
- src col Byte
- src row Byte
- target col Byte
- target row Byte
- useID UInt16
- random check Byte
- random Byte
then `Network.Send(50, 1, sendBuffer)`.

This matches Kotlin BattleCommandHandler C:050-001 layout.

## Step 344 — Defend
UIFight sets 17001 and immediately calls DoClick on the current actor.

It is sent as ordinary C:050-001 kind=1 on the wire; Kotlin's KIND_DEFEND is an internal classification only.

## Step 345 — Escape
UIFight sets 18001 and immediately DoClick.

Guest escape is still separate C:011-001.

DoClick rejects fightWay 12 escape in LifePK and WorldBoss.

## Step 346 — Catch
UIFight sets 15002, then target DoClick validates catch-specific target restrictions before sending C:050-001.

The client checks include actor/player restrictions, target kind, scene NoCatch, NPC catchability semantics, level difference, duplicate owned/inn NPC, elephant riding skill and seal status, plus a special 38022 condition.

## Step 347 — Kotlin internal classification is valid
BattleCommandHandler's mapping of 17001/18001/15002 to internal DEFEND/ESCAPE/CATCH does not change wire compatibility.

The previous concern that these necessarily bypass a Lua GetSkillLv gate was based on conflating CaseSkill with SetConSkill and is withdrawn.

## Step 348 — Proven server enforcement gap
Kotlin special action kinds bypass normal KIND_SKILL validation, while Lua DoClick performs command-specific checks before send.

A forged C:050 can therefore bypass some client-only escape/catch restrictions unless the server independently validates them.

## Step 349 — Why no escape-style patch yet
Kotlin `EWarStyle` currently defines only NORMAL/BEQ/ARENA_PK/W5TO5/CITY_PK/DUNGEON and does not define DVT LifePK or WorldBoss style constants.

`EWar.WORLD_BOSS=26` exists, but Lua's rejection is explicitly on `ffWar_Style`, not EWar. Mapping war type to style without evidence would violate Lua-first rules.

## Step 350 — Closure
The exact manual command path and packet are now proven. No production patch is made where required style/scene/NPC ownership data is not yet modeled authoritatively.

The server's internal special-action representation remains, but command-specific validation is an explicit next audit target.
