# Batch Steps 281–290 — CaseSkill selection parity

Status: **COMPLETE — owner build gate pending.**

## Step 281 — Lua fallback default
DVT `FightField.CaseSkill` begins by assigning `role.useSkID = 10000` (hand attack).

Every failed selection gate therefore leaves the client on basic attack instead of the requested skill.

## Step 282 — Missing/zero skill
If skillId is zero or `skillDatas[skillId]` is missing, CaseSkill returns with hand attack selected.

Kotlin already rejects a forged non-basic C:050 skill ID with no SkillDef rather than executing an unknown skill.

## Step 283 — SkillData Except contract
`SkillData:Except()` is exact:
`return not (self.id == 21026)`.

Therefore 21026 is the sole exception for the CaseSkill gate using Except.

## Step 284 — Restricted fightWay gate
CaseSkill performs:
`if Contains(skillData.fightWay, 6, 7, 8, 14, 19) and skillData:Except() then return end`.

Thus for fightWay 6/7/8/14/19, any skill other than 21026 falls back to hand attack at client selection.

## Step 285 — Proven forged-command gap
Before this batch Kotlin validated side/target semantics for these fightWays but did not enforce the CaseSkill Except gate.

A forged C:050 could therefore request a skill that normal DVT CaseSkill would never select.

## Step 286 — Authoritative server gate
`BattleInstance.setPlayerAction` now rejects a non-21026 SkillDef whose fightWay is 6, 7, 8, 14 or 19.

The check occurs immediately after resolving SkillDef and before dead/revive and side legality.

## Step 287 — 21026 preserved
Skill ID 21026 remains exempt exactly as Lua defines. No additional exception IDs were invented.

## Step 288 — Learned-skill sources
For Player/Players/Divide Lua resolves skill level through `Role.player`; Kotlin player fighter snapshots positive learned normal + turn3 skills.

For FollowNpc Lua resolves `Role.GetFollowNpc(...):GetSkillLv`. Kotlin currently snapshots `npcDef.skills`, not an independently inspected pet learned-level table. This remains a source-parity boundary; no speculative replacement was made in this batch.

## Step 289 — Regression coverage
Extended `DvtBattleCommandSemanticsTest`:

- 21026 with the same fightWay remains queueable.

Existing non-battle, bow, summon, revive and duplicate-command tests remain.

## Step 290 — Batch closure
Server now preserves the Lua CaseSkill fallback boundary against direct/forged C:050 commands.

No Lua changed. No unknown skill formula or FollowNpc learning model was invented.
