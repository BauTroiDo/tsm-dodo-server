# Batch Steps 501–540 — Battle entry / enemy spawn

Status: **PRODUCTION PATCHED — runtime/build gate pending.**

## Symptom
Client enters battle scene, countdown runs and the local player renders, but the enemy NPC is absent.

This strongly narrows failure to role-record parsing/rendering rather than battle creation itself.

## Lua wire contract
FightField.RoleAppear reads every role in this order:
warType Byte; kind Byte; roleId Int64; mapNpcIdx UInt16; masterId Int64; col Byte; row Byte;
maxHp/maxSp/hp/sp UInt32; lv UInt16; upgradeLv Byte; element Byte;
conditional appearance data; then **soulEquipId UInt16 unconditionally**.

The trailing soulEquipId is consumed for player, follow NPC, ordinary enemy NPC and every other kind.

## Kotlin mismatch
BattleRoleSerializer serialized the base fields and conditional appearance but returned immediately.
It never wrote the trailing soulEquipId.

When serializeAll concatenated roles, RoleAppear consumed the first two bytes of the next fighter as the previous fighter's soulEquipId. All subsequent fields became misaligned. With the player serialized first, this directly explains a visible player followed by a missing/corrupt enemy record.

## Patch
BattleRoleSerializer now writes UInt16(0) after every role record.
Zero means no soul equipment and preserves exact RoleAppear alignment.

A regression test serializes a player followed by an enemy and verifies:
- each record ends with a zero UInt16;
- concatenated size is exact;
- enemy warType/kind begin immediately after the player's complete record.

## Additional checks
Map-NPC battle creation already constructs the enemy before sendBattleInit, places it at enemy col=0,row=center, and serializes all fighters. createNpcFighter uses npcDataId as roleId/npcId so Lua can initialize the duplicate from NPC data.

Therefore the missing trailing UInt16 is the first concrete wire-level defect matching the screenshot.

## Gate
Run ./gradlew test build, then enter the same battle and verify the enemy appears.
If it still does not, capture server battle-init logs and continue byte-for-byte from the now-aligned RoleAppear boundary rather than changing combat formulas.
