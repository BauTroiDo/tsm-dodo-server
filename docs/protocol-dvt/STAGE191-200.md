# Batch Steps 191–200 — Revive and dead-target semantics

Status: **COMPLETE — owner build gate pending.**

## Step 191 — fightWay 8 is revive-target selection
`FightField.UpdateSelectFrame` treats `fightWay == 8` separately from ordinary friendly skills and calls `OpenSelectFrame(..., true)`, explicitly exposing dead friendly targets.

## Step 192 — Normal friendly target legality remains separate
`CheckSkillTargetLegal` includes fightWay 8 among skills that cannot target the enemy party. Revive therefore combines friendly-side legality with dead-target selection; it is not ordinary alive-friendly healing.

## Step 193 — Client positive-HP revive transition
Lua battle attribute handling proves the presentation transition: when an HP update changes a fighter from HP <= 0 to a positive value, the client clears the dead state and restores battle behavior/animation.

This establishes positive HP as the relevant revive state transition. It does not prove a new healing formula.

## Step 194 — Proven Kotlin mismatch
The friendly path previously called `BattleGrid.resolveTargets`, which alive-filtered normal areas.

For SINGLE, a dead selected target could also fall through to the normal living-target fallback. Thus a fightWay 8 revive could fail to select the corpse or silently retarget a living fighter.

## Step 195 — Dead-target-only resolver mode
`resolveTargets` now accepts `deadTargetsOnly`.

When enabled:
- occupied dead fighters are eligible;
- living fighters are ineligible;
- SINGLE never falls back from an invalid/living selected target to another living fighter.

Normal attack/heal/buff calls keep the previous alive-target policy.

## Step 196 — Scope only to fightWay 8
`BattleSkillResolver` enables dead-target-only mode only when `skill.fightWay == 8`.

This avoids weakening target legality for ordinary friendly healing, buffs, status skills, dispels or attacks.

## Step 197 — Server revive state
When a fightWay 8 HP-positive result raises target HP above zero, Kotlin now clears `isDead` and `isFlyOut`.

The S:050-001 result still carries the positive HP Attr_Kind/value, which is the client-visible state change consumed by the normal effect path.

## Step 198 — No invented revive formula
Healing amount remains the existing `calculateHeal` policy. This batch changes target eligibility and dead/alive state transition only.

No claim is made that the current heal formula is Lua-proven.

## Step 199 — Regression coverage
Added/extended tests for:
- dead target accepted in revive mode;
- living selected target rejected without fallback in revive mode;
- fightWay 8 resolves the selected dead ally;
- positive HP clears server dead state;
- unrelated living ally is not healed/retargeted.

## Step 200 — Batch closure
The server now preserves the DVT client distinction between ordinary friendly targeting and revive targeting.

Lua remains authoritative: fightWay 8 selects dead friendlies, while the positive HP result drives the revive transition.
