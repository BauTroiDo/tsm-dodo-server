# Batch Steps 351–360 — War-style constants and manual catch gates

Status: **COMPLETE — owner build gate pending.**

## Step 351 — Exact EFFWar_Style values
DVT FightManager.lua defines:
- LifePK = 11
- WorldBoss = 16
- NewChaos5to5 = 17
- NewMix5to5 = 26
- NewChaos5to5_100LV = 27

These are battle-style values and are distinct from EWar values.

## Step 352 — EWar distinction
DVT EWar has LifePk=21 and WorldBoss=26. Kotlin EWar already contains WorldBoss=26 but its EWarStyle model is incomplete.

Lua DoClick escape restriction explicitly reads ffWar_Style, so EWar.WORLD_BOSS must not be substituted for EFFWar_Style.WorldBoss.

## Step 353 — Server war-style modeling gap
BattleInstance currently stores warType (EWar) but no ffWar_Style-equivalent field.

Therefore exact LifePK/WorldBoss escape enforcement cannot yet be added without tracing/adding the style source through battle creation.

## Step 354 — NpcDef catch authority
Kotlin NpcDef already preserves the DVT fields required for core manual-catch target validation:
- kind
- canBeCatch (0 means allowed; represented as false)
- level

## Step 355 — Manual catch level rule
DVT DoClick for useID 15002 rejects when:
`npcDatas[target.npcId].level - actor.level > 5`.

This is an exact +5 limit.

## Step 356 — Existing constant was for another path
Kotlin CATCH_LEVEL_DIFF=40 was documented from MR_CatchLv/Attack.lua.

Fresh DVT DoClick shows MR_CatchLv is used by item 25085 (桃太郎飯糰), not manual catch skill 15002.

A separate MANUAL_CATCH_LEVEL_DIFF=5 is now defined.

## Step 357 — Queue-time target gate
Kotlin setPlayerAction now rejects manual catch when:
- target missing/dead;
- target is not on enemy side;
- target is Player/Players/FollowNpc;
- no authoritative involved NpcDef exists;
- NpcDef.canBeCatch says non-catchable;
- target NpcDef level exceeds actor level by more than 5.

This prevents forged C:050 from bypassing the proven core DoClick target rules.

## Step 358 — Unimplemented catch gates
Scene NoCatch, duplicate FollowNpc/Inn ownership, elephant riding-skill requirement, seal state and special NPC 38022 conditions require additional authoritative scene/account/status sources.

They are not guessed in this batch.

## Step 359 — Catch success formula warning
Current Kotlin resolveRound computes a 30–95% success rate from target HP and level difference.

No inspected DVT Lua evidence proves that formula. It remains an explicit UNKNOWN/non-authoritative area and should not be treated as Lua parity.

This batch does not replace it with another invented formula.

## Step 360 — Closure
Manual catch queue legality now follows the Lua-proven target and +5-level rules for data the server already owns. War-style escape validation remains blocked on BattleInstance lacking ffWar_Style.
