# Batch Steps 291–300 — FollowNpc learned-skill authority

Status: **COMPLETE — owner build gate pending.**

## Step 291 — Lua battle authority
DVT `FightField.CaseSkill` resolves FollowNpc through `Role.GetFollowNpc(Role.playerId, role.npcId)` and requires `oriRole:GetSkillLv(skillId) > 0`.

A FollowNpc skill ID existing in NpcData is therefore not sufficient by itself.

## Step 292 — Normal FollowNpc skill IDs
`RoleController:GetSkillLv` iterates the three base IDs from `npcDatas[self.npcId].skills[1..3]`.

## Step 293 — Per-pet levels
For those IDs Lua returns `self.data.skillLv[i]`.

Thus each individual FollowNpc owns the level state; level 0 means CaseSkill falls back to hand attack.

## Step 294 — Kotlin data model
`FollowNpcData` already persists:
- skill1Lv
- skill2Lv
- skill3Lv

`PetSkillSystem` already updates these fields against the corresponding first three NpcDef skill IDs.

## Step 295 — Proven battle snapshot gap
Before this batch `createFollowNpcFighter` populated:
`skills = npcDef.skills.filter { it > 0 }`.

That treated every configured base skill as learned even when this pet's corresponding skill level was zero.

## Step 296 — Battle snapshot fix
FollowNpc battle creation now zips the first three NpcDef skill IDs with this pet's skill1Lv/skill2Lv/skill3Lv.

Only IDs with both ID > 0 and level > 0 enter `BattleFighter.skills`.

## Step 297 — Skill levels preserved
The same authoritative pairs populate `BattleFighter.skillLevels`.

Battle area/growth logic can therefore use the actual pet level instead of defaulting merely from skill identity.

## Step 298 — Lua extended FollowNpc skills
`RoleController:GetSkillLv` also supports:
- learned special skill;
- upgrade skill;
- exclusive-weapon skill;
- passive skill;
- soul skills.

These are separate from the three normal per-pet levels.

## Step 299 — Evidence boundary
Kotlin has `canUseSpecialSkill`, `upgradeLv`, `soulId` and pet equipment fields, but the inspected server snapshot does not yet contain the full Lua-equivalent upgrade table, exclusive-weapon skill resolver or soul skill table.

This batch does not invent those mappings. Normal learned skills are fixed; extended FollowNpc skill parity remains PARTIAL.

## Step 300 — Closure
The server can no longer accept a forged C:050 normal FollowNpc skill merely because its ID exists in NpcDef when that individual pet has level 0.

No Lua changed. No soul/exclusive/upgrade skill mapping was fabricated.
